|---|---|

## Backend layout (`backend/app/`)

Each domain is a self-contained slice with `models.py` (SQLAlchemy), `schemas.py` (Pydantic), `service.py` (business logic), `routes.py` (FastAPI router). Routes call services; services own DB queries.

- `auth/` — Supabase JWT validation. `dependencies.py:get_current_user`, `get_current_team`, and `billing/enforcement.py:require_active_plan` are the auth + plan gates for every protected route.
- `platforms/` — `DataProviderRouter` adapter pattern. `base.py` is the abstract `DataProvider` ABC; `youtube.py`, `netrows.py`, `data365.py` are real adapters; `mock.py` is the deterministic fallback. `factory.py:build_router` picks real vs mock per provider based on env vars.
- `ai/` — Same shape as `platforms/`. `factory.py:get_ai_client` returns `ClaudeAIClient` if `ANTHROPIC_API_KEY` is set, else `MockAIClient`. Stashed on `app.state.ai_client` in `main.py` lifespan.
- `publishing/` — OAuth flows (`oauth_providers/`), scheduled post CRUD (`service.py`, `routes.py`), presigned upload flow (`common/storage.py`), publisher abstraction (`publishers/{base,mock,youtube,instagram}.py`), and `publisher_router.py`. All tokens encrypted at rest via `common/encryption.py`.
- `billing/` — Stripe integration (`base.py`, `mock.py`, `real.py`, `factory.py`), plan tier limits (`plans.py`), enforcement middleware (`enforcement.py`), checkout/portal/webhook routes. Mock-first: `MockStripeClient` when `STRIPE_SECRET_KEY` empty.
- `discovery/` — Trend search, outlier detection (Z-score in `outlier.py`), niches, `generate-idea` (AI brief endpoint).
- `analytics/` — Aggregation endpoints. All wrapped in 5-minute cache via `common/cache.py`.
- `workers/` — QStash-triggered HTTP endpoints (`scrape_creators`, `scrape_videos`, `discover_trends`, `publish_scheduled`). Signature-verified by `workers/middleware.py`. Not background processes — QStash POSTs to them on a cron.
- `common/` — `cache.py` (Upstash + in-memory fallback), `ratelimit.py` (same fail-open pattern), `pagination.py` (cursor-based), `errors.py`, `encryption.py`, `storage.py` (Supabase Storage + local disk fallback).

## Conventions and gotchas

- **Mock-first is the law.** Every external integration must work without an API key. If you add a new provider, write the mock adapter at the same time and wire it through the factory. The full app + tests must run with `.env` blank.
- **Async SQLAlchemy throughout.** No sync sessions. Tests use the same async engine via `tests/conftest.py`.
- **Cursor pagination, not offset.** All list endpoints use the helper in `common/pagination.py`.
- **Cache key hygiene.** When using `cached()`, prefix keys by domain (`analytics:overview:{team_id}`, `ai_brief:{video_id}`) so invalidation is tractable.
- **Rate limiting.** Apply via `Depends(rate_limit(...))` from `common/ratelimit.py`. AI brief endpoint is 10/hour/user; copy that pattern for any new expensive endpoint.
- **Plan enforcement.** Write endpoints use `Depends(require_active_plan)` from `billing/enforcement.py` instead of `get_current_team`. This blocks cancelled + trial-expired teams. GET endpoints keep using `get_current_team` (reads stay open).
- **Auth is Supabase, not custom.** Frontend uses the Supabase JS SDK directly. Backend only validates the JWT. Do not add register/login endpoints to FastAPI.
- **OAuth tokens are encrypted at rest** via `common/encryption.py`. Never log or return raw tokens. `ENCRYPTION_KEY` must be set in production (empty default — fails fast at startup if missing).
- **Migrations.** After editing any `models.py`, run `make migrate-create MSG="..."` and review the generated file before committing — autogenerate misses things like enum changes and CHECK constraints. Currently 2 migrations: `0001_initial` (13 tables) + `0002_team_stripe_customer_id_and_trial`.

## Testing

- **299 tests** across 33 files. `pytest-asyncio` with `asyncio_mode = "auto"`.
- `tests/conftest.py` provides the `client` fixture (triggers lifespan + disposes engine).
- `tests/test_creators.py` provides `authed_user` fixture, `_create_real_user()`, and `_upgrade_team_plan()` helpers — import these in any test file.
- Tests must not hit real APIs. Mock HTTP calls with `unittest.mock.patch`.
- Cross-team isolation tests are required for any new authenticated endpoint.
- Tests that need scheduling or multi-platform connections must call `_upgrade_team_plan(client, headers, "team")` first (Creator tier blocks these).
- Any fixture that creates `AsyncSessionLocal()` must call `await engine.dispose()` in teardown (asyncpg loop isolation).
- See `docs/TESTING.md` for the full testing guide.

## Workflow Orchestration

### 1. Plan Node Default
- Enter plan mode for ANY non-trivial task (3+ steps or architectural decisions)
- If something goes sideways, STOP and re-plan immediately - don't keep pushing
- Use plan mode for verification steps, not just building
- Write detailed specs upfront to reduce ambiguity

### 2. Subagent Strategy
- Use subagents liberally to keep main context window clean
- Offload research, exploration, and parallel analysis to subagents
- For complex problems, throw more compute at it via subagents
- One tack per subagent for focused execution

### 3. Self-Improvement Loop
- After ANY correction from the user: update `tasks/lessons.md` with the pattern
- Write rules for yourself that prevent the same mistake
- Ruthlessly iterate on these lessons until mistake rate drops
- Review lessons at session start for relevant project

### 4. Verification Before Done
- Never mark a task complete without proving it works
- Diff behavior between main and your changes when relevant
- Ask yourself: "Would a staff engineer approve this?"
- Run tests, check logs, demonstrate correctness

### 5. Demand Elegance (Balanced)
- For non-trivial changes: pause and ask "is there a more elegant way?"
- If a fix feels hacky: "Knowing everything I know now, implement the elegant solution"
- Skip this for simple, obvious fixes - don't over-engineer
- Challenge your own work before presenting it

### 6. Autonomous Bug Fixing
- When given a bug report: just fix it. Don't ask for hand-holding
- Point at logs, errors, failing tests - then resolve them
- Zero context switching required from the user
- Go fix failing CI tests without being told how

## Task Management

1. **Plan First**: Write plan to `tasks/todo.md` with checkable items
2. **Verify Plan**: Check in before starting implementation
3. **Track Progress**: Mark items complete as you go
4. **Explain Changes**: High-level summary at each step
5. **Document Results**: Add review section to `tasks/todo.md`
6. **Capture Lessons**: Update `tasks/lessons.md` after corrections

## Core Principles

- **Simplicity First**: Make every change as simple as possible. Impact minimal code.
- **No Laziness**: Find root causes. No temporary fixes. Senior developer standards.
- **Minimal Impact**: Changes should only touch what's necessary. Avoid introducing bugs.
